# 决策档案（DECISIONS）

每个关键决定：背景 → 决定 → 理由 → 被否决的备选。
格式仿 ADR，但保持轻量。**做过推翻决定的，两条都留着。**

---

## D1 采集走 WASAPI loopback，永不注入游戏进程
- **背景**：要拿精准声音信息，截获点有三——游戏混音内部（A）、系统音频会话（B）、送往声卡的最终流（C）。
- **决定**：截获点 B/C（loopback / 进程旁听），拒绝 A（注入）。
- **理由**：A 需要挂钩游戏进程内的音频中间件，是反作弊重点监控区，也是外挂技术路线。B/C 全是公开系统 API，与 OBS 录屏、Discord 语音同级。游戏无感知，零延迟影响。
- **被否决**：DLL 注入拿混音前结构化坐标——信息更精准，但性质变成外挂，一票否决。

## D2 频段归属放在分类器，不在触发器
- **背景**：v1 触发器带 low_ratio 门槛。
- **决定**：触发器只回答"有东西响了、响得多轻"（强/静双档 × 低/全/高三通道 surge）；频段归属由分类器判。
- **理由**：近处脚步"更亮"导致低频占比下降，频段门槛误杀真实目标。触发与分类解耦后，每类事件有自己的触发通道（玻璃走独立高频通道）。
- **被否决**：单一全频触发 + 更复杂的分类规则——分类器被迫处理所有帧，且 quiet 档无法实现。

## D3 单声道门限 corr < 0.95 剔除音乐床/人声
- **背景**：真实录像 8 分钟 1420 个 BGM 假脚步。
- **决定**：脚步类事件要求立体声相关度 < 0.95（静步档豁免，标低置信）。
- **理由**：音乐床/语音近单声道（p50 corr 0.999），游戏 HRTF 立体声天然去相关（p50 0.76）。这是区分"媒体内容"与"游戏信号"的最强特征，远超谱平坦度。
- **已知代价**：宽立体声电子乐可穿透（实测）；相关噪声床中静步依赖 quiet 档豁免。
- **被否决**：谱平坦度门限——电子鼓与脚步平坦度分布重叠，分不开。

## D4 枪声指纹 = attack 瞬态 150ms 的时间平均频谱形状
- **背景**：v1 时变包络指纹在连发场景类内距离爆炸（0.4-0.65）。
- **决定**：只取精调 onset 后 150ms，12 对数频带 × 左右耳，时间平均，L2 归一化，余弦最近邻。
- **理由**：连发时固定窗口必然混入前一发尾巴（0.3s 间隔 < 枪声尾音衰减）；枪的身份由枪管/制退器决定，写在 attack 频谱里；尾巴由距离/混响主导，混进去只拉大类内距离。实测同枪跨 400 秒 ≤0.15。
- **被否决**：① 全程 0.6s 窗（尾巴污染）；② 60/100ms 短窗（谱分辨率不足，实测更差）；③ 时变包络（对对齐误差过敏）。

## D5 90ms 决策延迟窗，峰值帧分类
- **背景**：触发落在起音斜坡，分类失败后冷却期吞掉真正的峰值帧。
- **决定**：触发后缓存 90ms，取窗内低频峰值帧做分类。
- **理由**：纠正"触发≠信息峰值"的时间差；代价是 90ms 延迟，对脚步/枪声可接受。
- **复用价值**：窗口机制是将来多人重叠脚步分离（onset 聚类）的容器。
- **被否决**：触发即分类（漏检）、冷却期缩短（治标不治本）。

## D6 距离档挂官方米数，行为声=可闻距离上界
- **背景**：距离估计算法（低频占比+响度）只能给粗档。
- **决定**：脚步档直接标 近≤15m/中≤32m/远≤49m（官方移动声音传播表）；行为声按官方可闻半径标上界（换弹≤27m、玻璃≤52m）。
- **理由**：官方表是地面真值级别的标定锚点；行为声"识别即距离"比估距更硬。UI 显示米数，决策直接。
- **被否决**：纯算法估距给具体米数——假精度，宁可给有出处的上界。

## D7 项目锚定 PC，放弃手机端雷达
- **背景**：曾考虑手机版（USB 声卡桥接 / Android App）。
- **决定**：手机端雷达类整个放弃，全部精力 PC。
- **理由**：手游官方内置"声纹"方向提示（ground truth 级），我们做是重复造轮子还更差；iOS 系统不允许第三方截获应用音频，无解。PC 版官方不提供声纹，信息空位真实存在。
- **被否决**：Android MediaProjection 内录 App（工程量几天，价值被官方声纹稀释）。

## D8 产品分层：个人全量版 / 商用降级版
- **背景**：商业化讨论（陪玩公司需求真实存在）。
- **决定**：降级版只含"音频过道"（EQ/压缩/降噪），可做硬件声卡形态售卖；感知层（雷达/人机过滤/枪型）保持个人工具，等平台白名单窗口（参考 PUBG 收编 DTS Sound Radar 先例）。
- **理由**：音频处理是外设正当功能，绿色无争议；感知层商用=把个人灰色规模化，腾讯法务有判例先例。红线：凡输出敌人位置信息的功能不进商品；商用形态下原始游戏音频不出用户机器。
- **被否决**：直接全量商用（赚快钱冒清零风险）。

## D9 LLM 接入分层：规则 <100ms / 本地小模型 1-3s / API 战后
- **背景**：贾维斯认知层怎么接 LLM。
- **决定**：三层延迟预算。即时警报永不走 LLM；战术建议层用本地 qwen3:4b（Ollama，OpenAI 兼容接口）；战后复盘用云端大 API（质量优先）。事件流先滚动聚合成结构化文本再喂。
- **理由**：成本一局几分钱、3-4B 小模型足够读结构化事件、隐私本地闭环。游戏时显卡被占但调用是脉冲式，影响可忽略。
- **被否决**：每事件直喂云端大模型（贵且慢）、纯规则战术推理（天花板低）。

## D10 检测哲学：只还原耳朵能听到的，一个比特不多要
- **决定**：系统不追求游戏内不存在的秘密信息；只做"人耳可解信号的机器化解"。
- **理由**：这决定了它在"感知增强"而非"作弊"的一侧；也给所有架构选择（loopback、本地闭环、不外传）提供了统一的价值锚。
